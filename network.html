Scam PAC Explorer

An interactive network visualization of PAC–vendor spending relationships from the 2023–2024 federal election cycle, built to help journalists, activists, and regulators identify fraudulent Political Action Committees.

Status Live
Started 2024
Tools Python · Dash · DuckDB · NetworkX · RapidFuzz · Amazon S3
Data FEC open API & bulk data · 2023–2024 election cycle

The question

Scam PACs — Political Action Committees that solicit donations under the pretense of supporting candidates but funnel nearly all receipts to fundraising vendors and insiders — have drawn increasing scrutiny from regulators and journalists. The FEC first flagged the pattern in 2016. A decade later, the practice remains largely unchecked.

This project asks: can we surface likely scam PACs systematically from the disclosure data PACs are already required to file? Three of the four key indicators — a high share of unitemized contributions, disproportionate spending on fundraising vendors, and minimal candidate support — are directly measurable from FEC filings. The fourth (whether PAC officers personally benefit from vendor payments) requires investigative reporting, but the first three can narrow the field considerably.

The approach

I collected all F3X filings from PACs active in the 2023–2024 cycle via the FEC's open API and bulk data store, then joined their Schedule B (operating expenditures) and Schedule E (independent expenditures) line items to trace every payment to a vendor, candidate committee, or other PAC.

The central challenge was vendor name standardization: the same vendor appears under dozens of spelling variations across thousands of filings. I evaluated HDBSCAN and Agglomerative Clustering but found accuracy insufficient for a tool whose output is inherently accusatory. I settled on RapidFuzz fuzzy string matching, which gave more predictable and auditable results.

The cleaned data is stored as Parquet on Amazon S3 and queried live via DuckDB — meaning every filter interaction in the app runs a SQL query against the full dataset rather than loading a 94 MB CSV into memory. The network is built with NetworkX and rendered in the browser with Dash Cytoscape.

Early findings

Filtering to PACs where 80%+ of receipts come from small-dollar unitemized donations and fewer than 10 distinct vendors received payments surfaces a tight cluster of committees spending almost entirely on direct mail and list acquisition services — with the same vendor names appearing across dozens of ostensibly unrelated PACs. The network visualization makes these shared-vendor relationships immediately legible in a way tabular data does not.

What's next

The current vendor standardization is rule-based. The next iteration will evaluate whether a fine-tuned ML clustering approach can improve recall without sacrificing the precision the accusatory nature of the output demands. I'm also exploring expenditure classification via NLP to automatically distinguish fundraising costs from genuine operational spending — which would make the scam PAC signal more precise without requiring manual review.

On the infrastructure side, I'm planning to migrate the data pipeline from local Jupyter notebooks to a cloud-native Spark or Databricks workflow to support full-cycle updates as new FEC filings are released.
